PC control (Windows-MCP add-on), part 2 of 2: troubleshooting. Part 1 is `refs/windows-mcp.md`, which arrived with the first PC-control call of this session.

- **Pop-up dialogs are invisible to Snapshot.** The add-on lists only windows that have both minimize and maximize buttons (v0.8.8 `desktop/service.py`), so a dialog never appears in Snapshot's window list, and the element scan can run out of room before reaching it. Use Screenshot (with a `region` if needed) and click by coordinates. (2026-10-19, GEN-908: Tableau's "Activate Tableau" dialog.)
- **Stuck add-on (GEN-920/933).** The add-on can freeze for a whole session (refusals with no countdown, one fixed generation). The approval check detects it, refuses other PC-control calls without a window (ControlStatus still runs) and gives the steps: (1) restart it yourself with `& "C:/Users/Erez/.claude/scripts/windows-mcp-restart.ps1"` from your own PowerShell tool (no window; it stops only this session's add-on, the next PC-control call starts a fresh one; it refuses a second restart within 10 minutes); (2) if the script refused or failed, or still stuck, or ControlStatus fails, Erez taps Ctrl, Shift, Alt, the Windows key, then Esc, hands off 10 s; (3) a new session. Ask Erez whether he is ready before each ControlStatus window; "ready" or another generation lifts the block. Say in your closing report whether the restart cured it, and take a new Snapshot before any label-based click. The desktop app's `/mcp` has no Reconnect button for an add-on it lists as connected (2026-10-26). In a PC-control task, move or focus windows with the App tool, not your own PowerShell (GEN-933).
- **The add-on works in every folder.** (Updated 2026-10-18; it was folder-limited before the 2026-10-15 "Let Claude control the PC from any folder" change.) If its tools aren't in your list, load them with ToolSearch before telling Erez a desktop action can't be done. Never answer "I can only use the browser" without checking.
